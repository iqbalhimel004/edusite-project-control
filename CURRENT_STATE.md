## Last approved work
### Architecture planning — APPROVED
Key approved decisions:
- one reusable white-label frontend codebase;
- controlled per-school customization, not a free-form page builder;
- Next.js + React + TypeScript + Tailwind direction;
- server-first/render-first approach where supported;
- UI separated from domain models and data provider;
- mock provider now, Frappe provider later;
- bilingual-ready architecture, full bilingual UI deferred;
- approximately 9–10 major homepage visual sections, avoiding a scroll wall;
- results refer to internal school examinations, not SSC Board publishing;
- mobile routine requires a deliberate mobile pattern rather than a shrunken desktop table;
- no fake contact form success before a backend exists;
- initial mock datasets should remain small and realistic;
- theme/config system must support identity, tokens, section visibility/order and limited section variants.
